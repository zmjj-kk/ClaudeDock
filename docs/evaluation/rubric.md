# KamaClaude Agent 评测评分细则（Rubric v1）

> 适用范围：S7 分支（Subagents / Skills / MCP / Multi-agent）
> 配套文档：`docs/agent_evaluation_plan.md`（评测体系）、`docs/evaluation/report.md`（本次评测分数与改进意见）
> 评分原则：**沿执行链四层独立打分，每层百分制；证据锚定、确定性优先；安全指标不进加权**。

---

## 0. 总体结构

四层各 100 分，子项权重之和 = 100。总体成熟度按重要性加权合成（仅作参考索引，不作为安全门禁）：

| 层 | 主题 | 权重（合成总分的占比） |
|---|---|---|
| 第一层 工具层 | 可靠性与正确性 | 30% |
| 第二层 单步与轨迹层 | 过程合理性 | 25% |
| 第三层 端到端任务层 | 目标达成度 | 25% |
| 第四层 线上业务层 | 实际收益与损耗 | 20% |

> 总体成熟度 = Σ(各层得分 × 权重)，满分 100。安全相关项（第四层"安全硬门禁"、第一层"权限与安全边界"）单独标注 PASS/FAIL，不参与加权平均——任何安全项 FAIL 时，总分不构成放行依据。

---

## 1. 第一层：工具层（100 分）

**目标**：每个工具在正常 / 空结果 / 超时 / 权限失败 / 第三方异常 / 幂等六类输入下行为可预测、可诊断。

### 1.1 Schema 与类型校验覆盖（30 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 所有工具都有 `params_model`，缺参/错类型/越界统一抛 `schema_error` | 30 |
| 部分 | 有 `params_model` 的工具覆盖 ≥ 70%，缺失工具能在 `invoke_tool` 层被兜底 | 18 |
| 低档 | 多数工具无 `params_model`，缺参混入 `runtime_error` | ≤ 8 |

### 1.2 错误分类与"不抛异常"契约（25 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | `error_type` 枚举完整且每类都有对应事件；工具内部异常全部转 `ToolResult` 不向上抛 | 25 |
| 部分 | 分类基本齐全，个别工具漏配（KeyError→runtime_error） | 23 |
| 低档 | 工具直接抛异常导致 loop 崩溃 | ≤ 10 |

### 1.3 幂等性与重试安全（25 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 每个工具显式声明 `retryable_errors`；副作用工具 `runtime_error` 不重试；只读工具可安全重试；非幂等写入有去重 | 25 |
| 部分 | 分类正确但非幂等工具（如 `task_create`）无去重声明 | 22 |
| 低档 | `runtime_error` 无条件重试所有工具（含 bash/MCP/子代理） | ≤ 5 |

### 1.4 权限与安全边界（20 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 所有路径类工具都有 cwd 边界 + 越权拦截；危险命令有 deny/allow 双层规则 | 20 |
| 部分 | 仅 `bash` 有启发式边界，`read_file`/`list_dir` 无绝对路径拦截 | 11 |
| 低档 | 无任何路径边界，任意工具可读任意路径 | ≤ 4 |

## 2. 第二层：单步与轨迹层（100 分）

**目标**：给定一步能判定"下一步动作"；给定整条轨迹能校验"必须出现 / 禁止出现 / 先后依赖"三类约束，并监控无效/重复调用与 Token/时间消耗。

### 2.1 可观测性原料（事件流完整性）（40 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 事件流覆盖 run/step/tool/usage/permission/subagent/skill 全量，且工具输出正文可检索 | 40 |
| 部分 | 事件类型齐全（含 failed 的 attempt 字段），工具结果正文未结构化落盘 | 34 |
| 低档 | 仅 stdout 日志，无可回放的事件流 | ≤ 10 |

### 2.2 轨迹校验器（三类约束）（30 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 有 `TrajectoryValidator`，支持 must_include / must_not_include / ordering 声明式校验 | 30 |
| 部分 | 有手动断言，无通用校验器 | 12 |
| 低档 | 无轨迹校验能力 | 0 |

### 2.3 负向指标聚合（无效/重复/Token/时间）（30 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 自动聚合无效调用率 / 重复调用率 / Token / 耗时，输出结构化报告 | 30 |
| 部分 | 原料可算（事件在），但无聚合器 | 6 |
| 低档 | 无任何度量 | 0 |

---

## 3. 第三层：端到端任务层（100 分）

**目标**：用环境状态 / 单元测试 / 结构化业务字段判定"任务是否达成"，拒绝 agent 自评；重复运行（pass^k）检验稳定性。

### 3.1 端到端执行能力（30 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 有确定性 harness，可离线跑完整 run 并采集结果 | 30 |
| 部分 | 有 smoke test 走通真实链路（依赖真实 API key） | 22 |
| 低档 | 无端到端执行 | 0 |

### 3.2 确定性成功判定（30 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 成功 = 环境状态 / 单测通过 / 业务字段校验，非 agent 自评 | 30 |
| 部分 | 仅断言 `status=="success"`（agent 自报），无外部 checker | 8 |
| 低档 | 成功判定依赖 agent 文本自述 | 0 |

### 3.3 稳定性 pass^k 与阶段进度（20 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 支持 pass^k 与 checkpoint 阶段给分 | 20 |
| 部分 | 有重复运行但无阶段拆解 | 8 |
| 低档 | 未实现 | 0 |

### 3.4 沙箱隔离（20 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 独立 cwd / runs_dir / 配置 / 权限剧本，可并行安全运行 | 20 |
| 部分 | 仅测试内 tmp_path + chdir，无专门 harness | 6 |
| 低档 | 无隔离，副作用污染宿主 | 0 |

---

## 4. 第四层：线上业务层（100 分）

**目标**：监控任务解决率、人工接管率、延迟分位、Token 成本、稳定性；安全指标独立成档。

### 4.1 遥测采集（35 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | trace/events/logs 三路采集 + 可查询视图 + 隐私去敏 | 35 |
| 部分 | 三路采集齐 + `kama trace` 查看器，但 `include_llm_payload` 默认开、未去敏 | 30 |
| 低档 | 无遥测 | 0 |

### 4.2 业务指标聚合（35 分）

| 档位 | 锚点 | 得分 |
|---|---|---|
| 满档 | 自动聚合解决率 / 接管率 / 延迟 P50/P90/P99 / Token 成本 / 稳定性 | 35 |
| 部分 | 有部分手工统计 | 10 |
| 低档 | 无聚合 | 0 |

### 4.3 安全硬门禁（30 分）★独立成档，不参与加权

| 档位 | 锚点 | 得分 / 状态 |
|---|---|---|
| 满档 | 未授权调用率 / 敏感泄露率 / 注入成功率 / 越权读取率四指标独立监控，超标红灯 | 30 / PASS |
| 部分 | 有部分安全样本测试但无线上监控 | 10 / WARN |
| 低档 | 无安全门禁 | 0 / FAIL |

| 维度 | 证据 |

## 6. 版本与校准

- 本 Rubric 随评测集生长与人工评审持续校准（见计划 §8.2）。
- 任何一层因新增能力导致得分变化时，须同步更新本文件版本号并记录变更原因。
